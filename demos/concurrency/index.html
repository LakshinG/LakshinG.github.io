Interactive illustrations of the paper, not the project's own code. Concurrency Models is a written analysis of what happens when you move one language's concurrency model into another. These widgets act out two of its arguments in JavaScript. Read the full write-up on GitHub.

Concurrency models, translated

Erlang actors, Go channels, and Java shared memory each assume something different about where bugs come from. Moving a model into another language shows which parts are syntax and which parts are baked into the runtime.

    OTP gives Erlang this supervisor for free. Java has nothing like it, so the tracking, restart, state reset, and "don't lose the queued messages" logic all has to be written by hand. Turn the supervisor off to see a plain Java thread die and leave its mailbox piling up.

    Three ready channels: who gets picked?

    Messages are waiting on channels a, b, and c every time. Go's select picks among ready cases at random. Elixir's receive checks its patterns top to bottom, so the first one that matches always wins.

    Elixir receive

    To get Go's fairness in Elixir you'd have to pull the whole mailbox into memory and shuffle it, which is slow and fights how the BEAM is designed.

    The model matrix

    ModelHostFitWhat has to be faked
    Java shared memoryGoBest fitNothing. sync.Mutex and sync.RWMutex are native and give the same happens-before guarantees. It only goes against Go's "share by communicating" style.
    Erlang actorsGoNeeds simulationSelective receive. Go channels are FIFO, so skipping a message means popping and stashing it (O(n)), and chan interface{} drops type safety.
    Go channelsJavaNeeds simulationselect. SynchronousQueue and ArrayBlockingQueue cover channels, but waiting on several means polling or one shared untyped queue.
    Erlang actorsJavaNeeds simulationOTP supervision and memory isolation. Restarts are hand-built, and the shared heap lets references leak between "isolated" actors.
    Go channelsElixirNeeds simulationBlocking hand-off, via GenServer.call, which throttles throughput. Random select can't be represented cleanly.
    Java shared memoryElixirWorst fitShared memory itself. The BEAM bans it, so an Agent fakes it with message passing, turning a quick lock into an inter-process round trip.
